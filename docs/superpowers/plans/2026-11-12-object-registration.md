# Local Object Registration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Extend device readiness into real three-view local object registration and fresh-scan similarity comparison, ready for manual testing.

**Architecture:** A lazy WASM inference worker produces normalized DINOv2 image vectors. A controller owns native camera capture, transient images and cancellation; a separate IndexedDB store persists one versioned visual template. React renders this state through the existing basic Tailwind UI, with no account unlock or financial action.

**Tech Stack:** Existing React/TypeScript/Vite/Tailwind, native camera/canvas/IndexedDB/Web Worker, pinned `@huggingface/transformers` 4.3.2, Node tests and Playwright Chrome. Run with Node >=22.18.0.

**Spec:** [Approved object-registration design](../specs/2026-11-12-object-registration-design.md).

**Execution:** Native execution was already selected by the user. Implement sequentially here, then use one fresh whole-branch reviewer. Status: awaiting the user's plan review; do not start implementation yet.

## Global Constraints

- Keep the existing basic UI; visual redesign remains paused.
- Only one local object registration is supported initially.
- No raw photo, thumbnail, camera stream, private key or biometric metadata is persisted or uploaded.
- Feature 1's memory-only capture behavior remains unchanged.
- Scores describe visual similarity; they are not probabilities or security confidence.
- This first release reports the real comparison without an uncalibrated match/deny threshold.
- No mocked successful media, embeddings, model response or wallet state may stand in for end-to-end integration.
- Stop camera tracks on leaving the flow, hiding the tab, reset and unmount.
- A failed replacement leaves the prior record intact.
- No wallet continuation is shown in this release.

## Review Focus

1. Cancel/visibility changes during permission, model load, inference or save: old work cannot reactivate capture or overwrite the saved record (Tasks 1–3).
2. Reload/corrupt data/model mismatch: recognize only a complete compatible template; show an actionable re-enrollment/delete path (Task 2).
3. Cold/offline model loading: explicit progress, failure and retry; no eager download, external fallback or false success (Tasks 1 and 3).
4. Similar objects/backgrounds/poor frames: report real scores and quality limitations, never “authenticated” or an invented confidence percentage (Tasks 1 and 3).
5. Camera orientation and resource cleanup: crop matches the visible guide on portrait/landscape layouts and no hidden-tab camera remains active (Tasks 2 and 3; physical behavior also manual).

## File map and shared types

Create `web/src/object-registration/` with focused files: `types.ts` (contracts), `comparison.ts` (vector math), `capture-quality.ts` (crop/quality), `inference.worker.ts` (model), `inference-client.ts` (worker ownership), `template-store.ts` (IndexedDB), `controller.ts` (flow/resources), `ObjectRegistrationPage.tsx` (basic screen), `CapturePanel.tsx` (preview/review), `ComparisonResult.tsx` (scores). Reuse existing design tokens and controller subscription pattern; do not refactor the unrelated landing/design pages.

Contracts in `types.ts`:

```ts
type Embedding = number[]; // exactly 384 finite normalized values
type ModelIdentity = { modelId: string; revision: string; artifactSha256: string; processorSha256: string; runtimeVersion: string; embeddingSchema: 'dinov2-cls-l2-v1' };
type ObjectTemplate = { schemaVersion: 1; id: string; label: string; createdAt: string; model: ModelIdentity; views: [Embedding, Embedding, Embedding] };
type Comparison = { scores: [number, number, number]; topTwoMean: number; inferenceMs: number };
type QualityResult = { ok: boolean; reason: 'invalid' | 'dark' | 'bright' | 'blur' | null };
type EmbeddingResult = { vector: Embedding; inferenceMs: number; model: ModelIdentity };
```

Use `crypto.randomUUID()`, ISO timestamps, and a trimmed 1–60-character label. Do not store arbitrary extra fields. Worker protocol uses an operation ID on every request/response: load/progress/ready/embed/result/error. Main-thread cancellation terminates that worker, rejects the pending operation and starts a new worker only on an explicit retry. No WebGPU fallback.
